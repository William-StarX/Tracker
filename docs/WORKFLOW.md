# 项目关键阶段的主动调用

1.5 的改动是把调用时机交给 Agent 的长期工作指引。已有分析接口保持不变；工具目录增加 instructions 和 checkpoints，MCP 初始化携带相同 instructions，安装的 Skill 开启隐式调用。

| 阶段 | 应使用的组件与操作 |
|---|---|
| 接管陌生 Java 旧项目、制定改动计划前 | CodeTracker overview；已有有效结构证据或已知具体目标时可跳过 |
| 缺陷调查、追查代码沿革 | CodeTracker trace，限定相关方法、变量或代码块 |
| 模块、依赖、入口或测试结构变化，后续工作依赖旧概览 | CodeTracker overview 更新结构证据 |
| Java 代码审查、完成一批实现/重构/修复 | RefactoringMiner review，或无 Git 时 directories |
| 最终 Java 候选发生了后续变化、准备交付 | RefactoringMiner 对最终内容重新审查 |

两个组件分别安装、分别使用。只有另一个工具也可用且任务需要时才组合，不要求一个组件依赖另一个组件。

## 聊天与项目范围

在一次聊天中，Agent 遵循这些阶段规则，用户无需每轮重新点名工具。跨聊天继续项目时，宿主须仍加载 Skill/MCP；从任务记录恢复项目、报告引用和版本证据后再工作。Skill 不是聊天记录数据库，不会替宿主恢复全部对话。

保存完整报告以及很短的任务交接记录：项目标识、精确提交或内容指纹、分析范围、报告位置、状态/覆盖限制、已证实事实和待验证假设。无需把完整源码或所有历史塞入每次提示词。项目换了、HEAD 变化、未提交文件变化、引擎版本/参数/可用历史变化时，需要判断原证据是否仍适用。

overview 观察当前工作区，HEAD 不变也可能过期；trace 追踪指定提交，行号必须来自该提交，不能当作未提交修改的历史。固定提交报告可继续作为那个版本的证据，不能自动作为新候选的证据。partial 和错误必须保留。

## 宿主如何加载

- 支持 Skill 的宿主：安装包提供 install-skill --destination <宿主技能目录>。目录应由宿主自动发现；Codex 项目可使用 .agents/skills，用户目录按当前宿主实际配置选择。
- MCP 宿主：注册并连接服务器后，在初始化中读取 instructions；更新服务后重新连接。分析过程不需要重新安装或重新启动 Java 服务。
- 自建 SDK/HTTP Agent：读取 Client().describe() 或 GET /tools，把 instructions 纳入任务指引，把 checkpoints 用作阶段映射。SDK 本身没有监听宿主任务状态的能力。

Codex 的 [官方 MCP 说明](https://learn.chatgpt.com/docs/extend/mcp)说明了初始化 instructions 的使用；[Skill 文档](https://learn.chatgpt.com/docs/build-skills)说明了隐式选择与发现目录。其它宿主可能有不同的指引加载方式，应验证实际支持情况。

若宿主的长期项目指引支持 AGENTS.md 或同类文件，可以合并以下约定：

> 在相关 Java 项目关键阶段主动使用已安装的分析组件：陌生旧项目开始前梳理结构；历史相关的缺陷调查中追踪相关已提交元素；完成一批 Java 改动后以及最终候选变化后收集变更审查证据。使用前确认目标与版本；保留完整报告引用和 partial/error 状态。已有证据只有在目标和内容仍匹配时才可复用。记录工具不可用或覆盖不足，不把未执行的分析写成已完成。

## 执行保证与开销

这些改动使规则能够持续被宿主发现和传递，要求 Agent 在关键阶段主动调用。不会在每次对话、每次保存文件后运行全项目分析；不增加轮询、常驻 JVM、GPU、数据库或全量历史缓存。

“每个必需节点一定执行”需要宿主调度器绑定明确事件，调用工具并保存该候选对应的结果，再判断节点是否完成。仅注册 MCP、安装 Skill 或返回阶段元数据不构成这种强制执行机制。本版本没有接通 Multi-Agent 调度器，也没有修改父项目的流程。

install-skill 拒绝覆盖已有技能，避免丢失用户定制。生成的 runtime.local.json 仅绑定本机 Python/Java/cache 路径，不携带模型密钥或服务令牌，且应留在本机。分析报告仍可能包含用户源码与路径，沿用 PRIVACY.md 的边界。
